# 작업 브랜치 흐름과 커밋 수정 (branch workflow, amend, merge)

## 상황

공용 개발 브랜치에 바로 커밋하던 작업 방식을, 작업 단위로 브랜치를 따서 커밋·push 하고
개발 브랜치에 `--no-ff` 로 merge 한 뒤 그 브랜치를 로컬·원격에서 지우는 방식으로 바꿨다.
브랜치를 만든다는 게 실제로 무엇을 만드는 일인지, `--no-ff` 가 왜 커밋을 하나 더 남기는지,
이미 push 한 커밋에 `--amend` 를 하면 왜 그냥 push 가 막히는지를 짚어둘 것.
