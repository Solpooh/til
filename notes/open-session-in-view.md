# 오픈 세션 인 뷰 (OSIV, Open Session In View)

## 상황
물류 배차 시스템의 환경별 설정을 보니 로컬·테스트 등 일부 환경은 OSIV 를 명시적으로 끄고,
개발·운영 환경은 아무것도 적지 않아 기본값으로 켜진 채 돌고 있었다. 조회 코드 곳곳은
"OSIV 가 꺼져 있다"는 전제로 짜여 있는데, 운영 배포 직후 커밋 직전에 발행한 이벤트를
커밋이 끝난 것으로 잘못 판정해 후속 처리가 커밋 전 데이터를 읽는 사고가 났고, 그 원인 분석에
"운영에서는 켜져 있음"이 등장했다. 같은 코드가 설정 하나로 환경마다 다르게 동작한다는 점을 짚어둘 것.

## 내가 이해한 것

## 더 알아볼 것
- 켜짐과 꺼짐에서 데이터베이스 연결과 엔티티 관리 범위는 각각 언제 열리고 닫히나
- 꺼진 환경에서 컨트롤러·응답 변환 단계의 지연 로딩은 어떻게 되고, 대안은 무엇인가
- 켜진 환경에서 "지금 트랜잭션에 합류해 있는가"를 묻는 신호가 왜 믿을 수 없게 되나
- 스프링 부트는 왜 기본값을 켜짐으로 두었고, 운영에서 끄면 무엇이 깨질 수 있나
- 로컬·테스트와 운영의 설정이 다르면 테스트가 놓치는 것은 무엇인가
